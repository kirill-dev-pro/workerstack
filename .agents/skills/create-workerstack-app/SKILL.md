# Create a Workerstack App

## Overview

A new app goes from an empty directory to a live URL in one pass: scaffold the
smallest complete app, prove it locally, then host it on Bunderhost's
Cloudflare target. This skill is the path. `creating-workerstack-apps` is the
reference for what goes inside: schema, access, jobs, storage, realtime, the
oRPC graph. Read it before adding features.

## Before writing code

Workerstack runs in a Worker isolate: no browser, no native modules, no local
disk, no raw TCP, about 128 MB of memory, short jobs. If the product needs a
headless browser, Postgres or MySQL, files of hundreds of MB, or jobs that run
for minutes, say so and stop: Workerstack is the wrong platform for it.

## Workflow

1. **Install the skills and the package** in the new directory:

   ```sh
   git init
   bunx workerstack skills
   bun add --exact workerstack@latest
   O=$(jq -r '.peerDependencies["@orpc/server"]' node_modules/workerstack/package.json)
   bun add @orpc/client@$O @orpc/server@$O @orpc/openapi@$O @orpc/json-schema@$O \
     @orpc/publisher@$O @orpc/valibot@$O @orpc/tanstack-query@$O \
     drizzle-orm drizzle-valibot@0.4.2 @libsql/client better-auth valibot \
     react react-dom @tanstack/react-query @tanstack/react-router @tanstack/react-start
   bun add -d @cloudflare/vite-plugin wrangler drizzle-kit@^0.30.0 vite \
     @vitejs/plugin-react typescript@^5.8.0 @types/react @types/react-dom @types/bun
   ```

2. **Write the starter files** from [starter files](references/starter-files.md):
   package.json scripts, Vite, TypeScript and Drizzle config, `.gitignore`,
   schema, backend, client, session, router, routes, and a test. Rename the
   example entity to the product's first one.
3. **Choose sign-in.** Email and password is in the starter. For a Klaud group
   (Telegram and other communities), see [sign-in with Klaud](references/klaud-sign-in.md).
4. **Generate and check**, in this order. The blueprint records the
   migrations, so generate them first; regenerate the blueprint after any
   change to the schema, access rules, or env.

   ```sh
   bun run db:generate    # migrations/ from the schema
   bun run blueprint      # workerstack.blueprint.yaml
   bun test
   bun run build          # also generates src/routeTree.gen.ts
   bun run typecheck
   bun run blueprint:check
   ```

5. **Run it**: `bun run dev`, then in a browser create an account, write a
   row, reload a private page (the session survives SSR), and sign out.
6. **Commit and push** to a GitHub repository; the blueprint and
   `migrations/` go in.
7. **Host it** on Bunderhost following [shipping](references/shipping.md):
   resolve the repository, create the project on the Cloudflare target, set
   secrets through a setup session, deploy the exact commit, and verify.

## Common mistakes

| Symptom                                             | Cause and fix                                                                                                                                |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| One user's data appears in another's SSR page       | A `QueryClient` at module scope lives for the whole isolate. Create it per router, as the starter does.                                      |
| `FORBIDDEN` listing a table with `list: 'owner'`    | `owner` checks a row, and a list has none. Use `list: 'authenticated'` with `scope.read: (ctx) => ({ userId: ctx.user?.id ?? '__none__' })`. |
| A test fails with `INTERNAL_SERVER_ERROR` on create | `t.auth.mockSession` fakes a session without a user row, and the table's foreign key to `user` fails. Use `t.auth.signUpEmail`.              |
| `workerstack build`: blueprint missing or stale     | Access rules and env are in the manifest. Run `bun run blueprint` after changing them.                                                       |
| Typecheck cannot find `./routeTree.gen`             | It is generated by `dev` and `build`; run one first.                                                                                         |
| `bun add -d typescript` installs 7.x                | Pin `typescript@^5.8.0`.                                                                                                                     |
| `/api/auth/*` hangs in the Worker                   | Something fetches while auth initializes, such as Better Auth `discoveryUrl`. List the OAuth endpoints instead.                              |
| `src/client.ts` breaks hydration                    | Reserved TanStack Start entry; the client lives in `src/api.ts`.                                                                             |
| `import { app }` from the backend                   | A Worker has no app instance; import `type App` only, and read the session through `src/session.ts`.                                         |
